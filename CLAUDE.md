## Project Overview

This is an Angular-based attendance tracking application for the Ak-Sar-Ben Amateur Radio Club. The application allows tracking member attendance at club meetings using call sign search and displays member information.

## Project Structure

- **`attendance-app/`** - Angular 19 application (standalone components)
  - **`src/app/components/attendance/`** - Main attendance tracking UI component
  - **`src/app/services/`** - Services for roster data and attendance management
    - `roster.service.ts` - Loads member roster data
    - `attendance.service.ts` - Manages attendance records in localStorage
  - **`public/`** - Static assets served by Angular
    - `members.json` - Unified member roster containing name, callsign, and club affiliations for both AARC and BARC members
    - `photo-map.json` - Mapping of callsigns to photo file extensions (generated by `build_photo_map.py`)
    - `pictures/` - Directory for member photos (fetched from QRZ.com)
- **`merge_rosters.py`** - Python script to merge AARC and BARC rosters into unified members.json
- **`build_photo_map.py`** - Python script to scan pictures directory and generate photo-map.json
- **`fetch_qrz_photos.py`** - Python script to download member photos from QRZ.com API

## Common Development Commands

### Angular Application

**Navigate to the Angular app directory first:**
```bash
cd attendance-app
```

**Development server:**
```bash
ng serve
# App runs at http://localhost:4200/
```

**Build for production:**
```bash
ng build --configuration production --base-href /ad/
```

**Run tests:**
```bash
ng test
```

**Watch mode (rebuilds on file changes):**
```bash
ng build --watch --configuration development
```

### Deployment to GitHub Pages

**Build and deploy (from `attendance-app/` directory):**
```bash
ng build --configuration production --base-href /ad/
npx angular-cli-ghpages --dir=dist/attendance-app/browser
```

**Note:** The `base-href` must be `/ad/` to match the repository name for GitHub Pages deployment.

### Python Photo Fetcher

**Fetch member photos from QRZ.com:**
```bash
python3 fetch_qrz_photos.py
```

Requires QRZ.com XML subscription credentials configured in the script.

## Key Architecture Details

### Data Flow

1. **Roster Data:** The `members.json` file contains a unified list of members with name, callsign, and club affiliations (AARC, BARC, or both)
2. **Member Structure:** Each member has: `{ name: string, callsign: string, clubs: string[] }`
3. **Attendance Storage:** Uses browser localStorage for persistence via `AttendanceService`, includes club affiliations in each attendance record
4. **Component Architecture:** Uses Angular standalone components (no NgModule)

### Member Search

The `RosterService.searchByCallsign()` method performs case-insensitive partial matching on callsigns. Results update as the user types in the search field.

### Attendance Records

- Stored in localStorage under key `'attendance_records'`
- Each record contains: `{ callsign, name, timestamp, clubs }`
- Prevents duplicate attendance entries for the same callsign
- Can be exported as JSON with club name and timestamp metadata
- Club affiliations (AARC, BARC, or both) are displayed as badges in the UI

### Angular Material

The app uses Angular Material 19 components for the UI (cards, chips, buttons, forms, toolbar, etc.). All Material modules are imported directly in the standalone `AttendanceComponent`.

## Important Notes

- **Callsign Requirement:** Members without callsigns are automatically filtered out and not displayed in the application
- **Multi-Club Support:** Members can belong to AARC, BARC, or both clubs. Each member has a `clubs` array indicating their affiliations
- Members appearing in both club rosters are identified by matching callsigns and display both club badges in the UI
- **Updating Roster Data:**
  - The source roster files are in the root directory
  - Run `python3 merge_rosters.py` to regenerate `attendance-app/public/members.json` from the source files
  - The unified `members.json` file must be in `attendance-app/public/` to be served by the Angular app
- **Updating Photo Map:**
  - After adding/updating member photos in `attendance-app/public/pictures/`, run `python3 build_photo_map.py` to regenerate the photo map
  - The photo map is used by the browse component to efficiently display photos without attempting to load non-existent images
- The app is deployed to GitHub Pages at `https://payne.github.io/ad/`
- Router warnings can be ignored if routing is not actively used
